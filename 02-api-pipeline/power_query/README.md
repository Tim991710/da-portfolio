# Power Query: как подключить

Power BI на этой машине не установлен, поэтому запросы лежат текстом —
их нужно вставить вручную. Это нормальный путь: `issues_api.m` — исходник,
а не готовый `.pbix`.

## Порядок

1. Power BI Desktop → `Главная → Получить данные → Пустой запрос` → `Расширенный редактор`.
2. Создать пять параметров (`Управление параметрами`):

| Параметр | Тип | Значение |
|---|---|---|
| `pBaseUrl` | Текст | `https://api.github.com/repos/duckdb/duckdb/issues` |
| `pState` | Текст | `open` |
| `pPerPage` | Целое | `100` |
| `pMaxPages` | Целое | `30` |
| `pExpectedCount` | Целое | `1292` |

3. Создать запрос `issues_raw`, вставить блок из `issues_api.m`.
4. Создать запрос `issues_checks`, вставить второй блок.

## Что здесь важно технически

- **Пагинация по номеру страницы.** Останавливаемся, когда страница вернула пустой
  список, и страхуемся `pMaxPages`: если источник «залип» и всегда отдаёт последнюю
  страницу, запрос не уйдёт в бесконечный цикл.
- **Контроль кода ответа.** `ManualStatusHandling` не даёт Power Query тихо
  превратить 403 в пустую таблицу — иначе отчёт обновится «успешно» без данных.
  Отдельно обработан случай, когда 403 означает исчерпанную квоту.
- **Разворачивание по одному полю** (`try [raw][field] otherwise null`).
  Автоматическое «Развернуть» падает, если в части записей поле отсутствует.
- **`is_pull_request`.** В GitHub `/issues` попадают и PR — 44% выгрузки.
  Без флага все метрики по обращениям завышены почти вдвое.
- **`Table.Distinct` по `number`.** Проверка на дубли при повторной загрузке
  страницы.

## Перенос на другой источник

Меняются три вещи: `pBaseUrl`, имя параметра страницы (у части API это
`offset`/`skip`) и список полей при разворачивании. Логика пагинации,
контроля кода и дедупликации остаётся.

Если API отдаёт общее число записей (`total`, `count`), подставьте его
в `pExpectedCount` — проверка полноты станет автоматической.

## Ограничение

GitHub без токена даёт 60 запросов в час; выгрузка занимает 13.
В продакшене токен кладут в `Web.Contents` через `Headers` и хранят
в параметре, а не в тексте запроса.
