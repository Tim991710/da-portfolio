# Как собрать дашборд в Power BI Desktop

Power BI Desktop на этом компьютере не установлен — его нужно поставить один раз.
Всё остальное (данные, SQL, меры) уже готово.

## 0. Что уже лежит в проекте

| Папка | Что внутри |
|---|---|
| `data_gen/generate_data.py` | генератор сырья «как из iiko» (CSV в windows-1251) |
| `data/raw/` | сырые выгрузки: продажи, ФОТ, план, техкарты, справочник точек |
| `sql/01_schema.sql` | схема витрин |
| `sql/02_marts.sql` | построение dim/fact и мартов, правила расчёта |
| `sql/03_checks.sql` | 11 проверок качества |
| `sql/build_db.py` | загрузка CSV → SQLite → витрины → проверки → экспорт |
| `data/marts/` | готовые таблицы для Power BI (CSV, UTF-8) |
| `power_bi/dax_measures.dax` | библиотека мер |

## 1. Установка Power BI Desktop

1. Microsoft Store → «Power BI Desktop» → установить (бесплатно).
2. Альтернатива: сайт Microsoft → Power BI Desktop → Download (нужна учётная запись Microsoft).

## 2. Пересобрать данные (если менял генератор)

```powershell
python data_gen/generate_data.py
python sql/build_db.py
```

Второй скрипт печатает результат 11 проверок. Все строки должны быть `OK`,
кроме `C7 Полнота ФОТ` — там `WARN` стоит намеренно (пропуск выгрузки по T05).

## 3. Загрузить таблицы

`Главная → Получить данные → Текст/CSV` — по очереди, из `data/marts`:

`dim_date.csv`, `dim_outlet.csv`, `dim_dish.csv`, `fact_sales.csv`,
`fact_payroll.csv`, `fact_plan.csv`, `mart_monthly_outlet.csv`,
`mart_plan_fact.csv`, `log_data_quality.csv`, `quarantine_sales.csv`.

В диалоге: **кодировка UTF-8**, разделитель — запятая, «Данные содержат заголовки».
Дальше «Преобразовать данные»:

- `dim_date[date_key]` → тип **Дата**;
- `fact_sales[date_key]` → **Дата**;
- `fact_payroll[month_start]`, `fact_plan[month_start]`,
  `mart_*[month_start]` → **Дата**;
- `quarantine_sales[amount_paid]` → **Десятичное число**;
- остальные числовые оставить как есть.

«Закрыть и применить».

## 4. Модель

Вкладка «Модель». Связи (все — «один ко многим», направление фильтра
**одинарное**, от справочника к факту):

| Из | В | Ключ |
|---|---|---|
| dim_date | fact_sales | `date_key` |
| dim_date | fact_payroll | `month_start` |
| dim_date | fact_plan | `month_start` |
| dim_outlet | fact_sales | `outlet_code` |
| dim_outlet | fact_payroll | `outlet_code` |
| dim_outlet | fact_plan | `outlet_code` |
| dim_dish | fact_sales | `dish_code` |

Затем: выделить `dim_date` → «Таблица даты» → `date_key`.
Скрыть от просмотра технические ключи в фактах (`date_key`, `outlet_code`,
`dish_code`, `month_start`) — в отчёте они не нужны.

`mart_monthly_outlet` и `mart_plan_fact` не связывать с моделью: это витрины
для сверки, на них проверяем, что меры на звезде дают те же цифры.

## 5. Меры

`power_bi/dax_measures.dax` — открыть, копировать меры по одной в
«Создать меру» (после каждой формулы — Enter, иначе DAX не примет).
Разложить по папкам отображения: `01 Базовые`, `02 Показатели`,
`03 План-факт`, `04 Контекст`.

Проверка после сборки: карточка `Выручка` = **51 421 860,25 ₽**.
Если не совпало — почти всегда дело в связи `fact_payroll/fact_plan`:
они должны цепляться к `dim_date` по `month_start`, а не по `date_key`.

## 6. Страницы

**С1 «Сводка сети»**
- 5 карточек: Выручка, План выручки, Выполнение плана %, Доля ФОТ %, Операционная рентабельность %.
- Линейчатая с накоплением: Выручка и План выручки по `dim_date[month_start]`.
- Гистограмма: Доля ФОТ % по `dim_outlet[outlet_name]`.
- Матрица: строки — месяцы, столбцы — точки, значение — Доля ФОТ %, условное форматирование «цветовая шкала».
- Срезы: `dim_date[year]`, `dim_outlet[city]`.

**С2 «Точки»**
- Точечная: X — Выручка, Y — Операционная рентабельность %, размер — Чеков, цвет — город.
- Гистограмма: Средний чек по точкам.
- Таблица: точка, выручка, food cost %, доля ФОТ %, рентабельность, `Статус плана` (условное форматирование по статусу).

**С3 «Разбор отклонения»**
- Срезы: точка (один выбор), месяц.
- Карточки: Плановая доля ФОТ %, Доля ФОТ %, Отклонение доли ФОТ, п.п.
- Waterfall: в Power BI он не берёт две меры сразу, поэтому создаём
  «Ввести данные» таблицу `var_steps` с колонками
  `Шаг` = План / Эффект выручки / Эффект ФОТ / Факт и меру `SWITCH` по шагу,
  которая возвращает соответствующее отклонение. Категория — `var_steps[Шаг]`.
- Текстовое поле с выводом по выбранной точке (текст писать под каждый случай руками — это нормально).

**С4 «Качество данных»**
- Таблица `log_data_quality`: проверка, метрика, статус.
- Карточка: количество проверок со статусом не `OK`.
- Таблица `quarantine_sales` — 12 строк, которые не попали в выручку.

## 7. Оформление

- `Вид → Темы` — одна тема на весь отчёт, без пестроты.
- Заголовки страниц одним стилем, подписи осей — по-русски.
- На каждой странице — сноска: «Данные синтетические, учебный проект».
- Числа: ₽ — `# ##0 " ₽"`, проценты — `0,0 %`, п.п. — `+0,0 " п.п.";-0,0 " п.п."`.

## 8. Экспорт и скриншоты

1. `Файл → Экспорт → Экспорт в PDF` — положить в `screenshots/`.
2. Скриншоты страниц: `01-summary.png`, `02-outlets.png`, `03-variance.png`, `04-quality.png`.
3. Скопировать `dashboard.pbix` в папку `power_bi/`.

## Если что-то не сходится

| Симптом | Причина |
|---|---|
| Кириллица в CSV «кракозябрами» | не указана кодировка UTF-8 при импорте |
| `Выручка` = BLANK | связь `dim_date` → `fact_sales` идёт не по `date_key` |
| ФОТ умножился на количество дней | `fact_payroll` связан с `dim_date` по `date_key` вместо `month_start` |
| Мера не создаётся | скопирован блок из нескольких мер сразу |
| Сумма выручки больше 51,4 млн | в модель попал `mart_monthly_outlet` и сложился с фактом |
